# Service defaults

How the manager fills in a pushed service's category, icon, image URL and display name from
configuration. This is step 2 of the write path in [managers.md](managers.md#the-write-path).
It runs once per incoming service, before the per-dashboard merge.

## The factory

[`ServiceWithDefaultsFactory`](../../src/Dsm.Managers/Services/ServiceWithDefaultsFactory.cs)
has one public method:

```csharp
public Service CreateWithDefaults(Service service);
```

It returns a new `Service` record and never mutates its input.
[`DashboardCommandProcessor`](../../src/Dsm.Managers/DashboardCommandProcessor.cs) calls it
for every service that survives filtering, after stamping `Autogenerated = true`.

### Finding the defaults entry

The lookup key is the service's `ServiceDefaultsName` if it has one, otherwise its `Name`.
`ServiceDefaultOptions.Services` compares keys case-insensitively, so `PiKVM`, `pikvm` and
`PIKVM` all find the `pikvm` entry.

`ServiceDefaultsName` lets a provider point a service at a different entry. Containers set it
with the `<prefix>.service_defaults_name` label; YAML-file services set it with the
`service_defaults_name` key. Either way, a container named "Plex Beta" can use the `plex`
defaults.

### What each field gets

For `Category`, `Icon` and `ImageUrl`, the service's own value wins and the defaults entry only
fills a field that is empty. `Name` follows its own rule.

| Field | Result |
|---|---|
| `Category` | The service's own category, else the entry's `Category`. |
| `Icon` | The service's own icon, else the entry's `Icon`. A prefix form such as `hl-jellyfin` is kept as written; [icons.md](icons.md) resolves it per dashboard. |
| `ImageUrl` | The service's own `ImageUrl`, else the entry's `ImagePath`. Either way it then goes through [image URL resolution](#image-url-resolution). |
| `Name` | If the entry has a `NameWithHostnameFormatString` and the service has a `Hostname`: the format string with `%s` replaced by the hostname (`Traefik (%s)` → `Traefik (media-01)`). Otherwise the service's own name. A format string with no `%s` works as a fixed display name, e.g. `Open WebUI`. |
| `ServiceDefaultsName` | The service's own value. If it had none and an entry matched, the lookup key that matched. Otherwise empty. |
| `Url`, `Hostname`, `Ignore`, `Autogenerated`, `ProviderId` | Copied unchanged. |

The `ServiceDefaultsName` stamp keeps the original defaults key after `Name` has been rewritten
(`adguardhome` → `AdGuard Home (network-01)`). The Homepage widget matcher needs that key
([managers.md](managers.md#service-widgets)). Homepage stores it in `services.yaml` as
`_serviceDefaultsName`, so it survives a round trip through the file.

### Image URL resolution

The image value (the service's `ImageUrl` or the entry's `ImagePath`) is resolved like this:

- An absolute `http://` or `https://` URL is used directly.
- A relative path is resolved against the service's `Url` when that is an absolute URI:
  `/favicon.png` with `https://grafana.example/` gives `https://grafana.example/favicon.png`.
- Anything else passes through unchanged, and the dashboard decides what to do with it.

## service-defaults.yaml

[src/service-defaults.yaml](../../src/service-defaults.yaml) ships with the Manager API.
`Dsm.Managers.csproj` copies it next to the binary. It's loaded at startup as a required
configuration file, so the manager doesn't start without it. Everything sits under
`ServiceDefaultOptions` ([ServiceDefaultOptions.cs](../../src/Dsm.Managers/Configuration/ServiceDefaultOptions.cs)):

```yaml
ServiceDefaultOptions:
  FallbackIconSourceProviders:
    - HomarrLabs
    - SelfhSt
  Categories:
    ai:
      Name: AI
      Icon: mdi-assistant
    media:
      Icon: mdi-multimedia
  Services:
    adguardhome:
      NameWithHostnameFormatString: AdGuard Home (%s)
      Category: network
      Icon: hl-adguard-home
    plex:
      Category: media
```

- **`Services`**: per-service entries, keyed by lookup name. Each value is a
  [`ServiceConfig`](../../src/Dsm.Managers/Configuration/ServiceConfig.cs) with
  `NameWithHostnameFormatString`, `Category`, `Icon` and `ImagePath`.
- **`Categories`**: per-category entries, keyed case-insensitively by category name. Each
  value is a [`CategoryConfig`](../../src/Dsm.Managers/Configuration/CategoryConfig.cs):
  - `Name` overrides the display name.
  - `Icon` becomes the Dashy section icon or the Homepage layout icon.

  How the two dashboards name and decorate categories is in
  [managers.md](managers.md#categories).
- **`FallbackIconSourceProviders`**: the icon sources to try, in order, for a service that
  still has neither `Icon` nor `ImageUrl` after this step
  ([icons.md](icons.md#the-fallback-chain)). This chain applies to services only, not to
  categories.

## Overriding from manager-config.yaml

`manager-config.yaml` binds into the same `ServiceDefaultOptions` section and loads after
`service-defaults.yaml`, so its values win. `DSM_` environment variables load after both (see
[overview.md](overview.md#configuration)).

Overrides apply per key. A whole entry is never replaced. This example adds an icon to `plex`
and keeps its shipped `Category: media`:

```yaml
# manager-config.yaml
ServiceDefaultOptions:
  Services:
    plex:
      Icon: my-custom-plex-icon
```

Lists are overridden per index. Writing `FallbackIconSourceProviders: [HomarrLabs]` in
`manager-config.yaml` replaces index 0 only, so the effective list is still
`[HomarrLabs, SelfhSt]`. To drop an entry, set its index to an empty value. The binder skips
an element it can't convert, so `DSM_ServiceDefaultOptions__FallbackIconSourceProviders__1=`
leaves `[HomarrLabs]`. This is standard `Microsoft.Extensions.Configuration` behaviour, not
DSM-specific.
