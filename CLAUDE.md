# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Dashboard Services Manager (DSM) keeps a self-hosted dashboard's YAML config (Dashy `conf.yml`;
Homepage `services.yaml`, plus category icons in `settings.yaml`) in sync with the services
actually running, while keeping entries added by hand. Two .NET 10 processes:

- **Dsm.Provider.App** (on the `Dsm.Providers` library): one per host. Polls one or more
  sources (Docker, Docker Swarm, Traefik, a YAML file) and POSTs a `List<Service>` to the
  manager.
- **Dsm.Manager.Api** (on `Dsm.Managers`): the only process that writes dashboard files.

`Dsm.Shared` holds the `Service` wire record, the YAML config loader, Serilog setup and
constants. `Dsm.Managers` and `Dsm.Providers` never reference each other; `Service` as JSON is
the whole contract. Providers and the manager are deployed and versioned separately, so
changes to `Service` must stay backward compatible (new fields optional). The combiner's
null-`ProviderId` path exists for older providers.

Deeper docs are in `docs/development/` (overview, managers, providers, icons, service-defaults,
testing). Where they disagree with the code, the code and tests win.

## Commands

Run `dotnet test` from `src/`. `src/global.json` (SDK 10.0.100, `rollForward: latestMinor`)
switches `dotnet test` to Microsoft.Testing.Platform. From the repo root that file isn't found,
and `--solution` / `--project` fail with `MSB1001: Unknown switch`.

```sh
cd src
dotnet build Dsm.sln
dotnet test --solution Dsm.sln --filter "TestCategory!=Network"   # CI's gate; must pass offline
dotnet test --project Dsm.Managers.Tests --filter "FullyQualifiedName~ServicesCombinerTests"   # one fixture
dotnet test --project Dsm.Managers.Tests --filter "Name=AutogeneratedExisting_SameName_SameHostname_IsReplaced"   # one test
```

Run the API locally. It exits at startup unless at least one `DashboardManagers` entry is
configured. It serves `http://localhost:5270` (`/dashboard-services`, `/health`). Services
that still have no icon after defaults are applied trigger real HEAD requests to
cdn.jsdelivr.net.

```sh
DSM_ManagerOptions__DashboardManagers__0__DashboardManagerType=Dashy \
DSM_ManagerOptions__DashboardManagers__0__DashboardConfigDirectoryPath=$(mktemp -d) \
dotnet run --project src/Dsm.Manager.Api
```

The provider's env-var invocation is in `docs/development/overview.md#build-and-run`.
To run containers built from the working tree: `cd docker-compose && docker compose --env-file env up --build -d`.
The override file there adds the `build:` directives.

- **Packages:** every project restores with a `packages.lock.json`, and CI's test job and both
  Dockerfiles restore with `--locked-mode`. After changing a `PackageReference`, run a normal
  restore or build and commit every lock file that changed. Lock files of dependent projects
  change too. Refit is held back at 10.0.1 on purpose (505bf29: the newer release's signing
  cert was revoked).
- **Formatting:** nothing is enforced; CI has no format or lint step. `.config/dotnet-tools.json`
  pins CSharpier 0.22.1, but the code isn't formatted with it (67 of 135 files would change)
  and it needs a .NET 7 runtime. Don't run it repo-wide. Match the surrounding style.
- **Nix**, run by CI on every push to main and every PR: `nix flake check` and
  `nix build .#packages.<system>.dsm-provider`.

## Architecture

### Write path: `POST /dashboard-services`

`DashboardController` calls `DashboardCommandProcessor.UpdateWithServicesFromProvider`. Its
whole body runs under `DashboardWriteCoordinator`, a singleton `SemaphoreSlim`. Without it,
concurrent POSTs from different provider hosts would read, modify and write the same file and
drop each other's entries.

1. `ProviderServiceStore` (singleton, persisted to `/data/state.json`) replaces the copies of
   every `ProviderId` in the POST, as posted: ignored and URL-less ones included.
   - `StaleProviderTracker` expires silent ProviderIds (below).
   - With no state file, the store seeds itself once from the first dashboard's own entries.
2. `ServiceMerger` merges every source's copies of the same service, matched on
   `(Name, Hostname)` after defaults or on `(Url, Hostname)`.
   - Any ignored copy, or a name in `IgnoredServiceNames`, hides the service; so does having no
     URL.
   - `Url` comes from the first copy in Traefik, Docker, Swarm, YAML order. Other values come
     from Docker, Swarm, Traefik, YAML order. The type is parsed from the ProviderId suffix.
   - `ServiceWithDefaultsFactory` then fills only the gaps. It looks up defaults by
     `ServiceDefaultsName ?? Name`, rewrites `Name` from `NameWithHostnameFormatString` when there
     is a hostname, and resolves a relative `ImagePath` against `Url`.
3. For each `ManagerOptions.DashboardManagers` entry: `IDashboardManager.ListServices()`, then
   `ServicesCombiner` (keeps hand-written entries, replaces DSM's own with the merged set), then
   `WriteServices()`. `WriteServices()` resolves icons for DSM's own entries on that dashboard
   and writes through `YamlFileWriter.WriteIfChanged` (temp file + rename). It skips the write
   when the bytes match, because the dashboards watch these files.

A POST in which no service has a `ProviderId` (an old provider) skips the store and merge. It is
filtered, defaulted and combined with each file directly.

The response is keyed by manager type. `GET /dashboard-services` returns the merged state
instead: what DSM knows, without hand-written entries.

### Ownership and the combiner

DSM only replaces entries it wrote. The ownership marker (`_autogenerated`) and the fields the
combiner keys on are stored in the dashboard file itself:

- **Dashy:** item tags `_autogenerated`, `host=<Hostname>`, `provider=<ProviderId>`.
- **Homepage:** keys `_autogenerated`, `_providerId`, `_serviceDefaultsName`.

Entries without `_autogenerated` count as hand-written and survive replacement. They can still
lose the dedupe described below to a generated service with the same `(Name, Hostname)` or
`(Url, Hostname)`. A write rebuilds DSM's own entries from their `Service` records.
A surviving hand-written entry is written back from its YAML node, unchanged, with no status
check, widget or icon added. `YamlNodes.IndexHandWritten` finds that node by the `Service`
record the entry reads as. The same goes for Dashy section fields and top-level keys, and for
`settings.yaml`. Quoting survives; comments don't.

For POSTs with `ProviderId`s, `ServicesCombiner` replaces every autogenerated entry that has a
`ProviderId` with the merged set; hand-written and pre-`ProviderId` entries survive. For POSTs
without them, it falls back to hostname/name overlap. Either way it then dedupes on
`(Name, Hostname)` and then `(Url, Hostname)`, generated services first, and sorts by
`(Category, Name)` so the output is stable. `ServicesCombinerTests`, `ServiceMergerTests` and
`DashboardCommandProcessorTests` are the spec.

A source that stops posting keeps its copies in the store until `StaleProviderTracker`, a
singleton with in-memory timestamps, finds it silent for longer than
`ManagerOptions.StaleProviderTimeout` (default 1 h). Its copies are then removed. A manager
restart, or a gap with no POSTs at all, restarts every timeout. `StaleProviderTrackerTests` is the
spec.

### Icons resolve per dashboard, at write time

`Service.Icon` stays in prefix form (`hl-`, `sh-`, `mdi-`) through the whole pipeline and in
the POST response. GET reads icons back as they were written. `IconResolver` maps it
separately for each manager through
`IDashboardManager.NativeIconSourcePrefixes`; for example, Dashy keeps `hl-` while Homepage
wants HomarrLabs icons with no prefix. It sends HEAD probes to jsDelivr only in two cases: a
prefix the dashboard doesn't render natively, or the `FallbackIconSourceProviders` chain for
services with neither `Icon` nor `ImageUrl`. Icon sources are singletons with an in-process
cache: hits are kept forever, misses for 7 days.

### Configuration

- `AddNormalizedYamlFile` strips `_` from keys, so snake_case, camelCase and PascalCase all
  bind the same way.
- Manager config layers, later wins:
  1. `src/service-defaults.yaml`: required, and copied next to the binary by `Dsm.Managers.csproj`.
  2. Optional `manager-config.{yml,yaml}`: the relative path first, then under `/config/`.
  3. `DSM_` env vars: `__` nests keys, `__0` indexes lists.

  Lists are overridden per index, not replaced as a whole.
- Provider config layers: `provider-config.{yml,yaml}` (same two locations), then `DSM_` env vars.
- Options are validated on start (DataAnnotations plus `ManagerOptionsValidator` /
  `ProviderOptionsValidator`), so bad config stops the host. Duplicate `DashboardManagerType`
  entries are rejected.
- Setting `ManagerOptions.ApiKey` turns on `X-Api-Key` auth for the controller routes;
  `/health` stays open. `ProviderOptions.ApiKey` makes the provider send the header.

### Provider loop

`ProviderService` is a `BackgroundService` driven by a `PeriodicTimer` on `RefreshInterval`
(default 60 s):

- At startup it gives each `ServicesProviderConfig` a `ProviderId` of the form
  `{hostname}-{type}[-{index}]`, unless one is configured.
- Each tick it rebuilds every `IServicesProvider` through `ServicesProviderFactory`. A provider
  that throws is logged and skipped.
- It POSTs the combined list through the Refit `IDcmClient`, skipping the POST when the list is
  empty.
- It then touches `/tmp/dsm-heartbeat`. The provider image's HEALTHCHECK and the compose
  healthcheck both read that exact path.

`ServicesProviderFactory` and `DashboardManagerFactory` both build instances with
`ActivatorUtilities.CreateInstance(sp, config)`. The per-entry config is a constructor argument,
not `IOptions`.

### Adding things (each spans several files)

- **Dashboard:** implement `IDashboardManager`, add a `DashboardManagerType`, and extend the
  `DashboardManagerFactory` switch. The manager must write and read back the ownership marker.
  Otherwise the combiner treats its entries as hand-written and never replaces them. It must
  also write hand-written entries back from their YAML nodes (`YamlNodes`). Fill in
  `NativeIconSourcePrefixes` too: if it's empty, every prefixed icon is CDN-probed and written
  as a jsDelivr URL instead of being passed through. See `docs/development/managers.md`.
- **Provider:**
  - Implement `IServicesProvider` and stamp `_config.ProviderId` on each `Service`.
  - Add a `ServicesProviderType`, any nullable fields on `ServicesProviderConfig`, and a
    `ServicesProviderFactory` case.
  - Add a `ProviderOptionsValidator` case for its required fields.
  - Update the provider `type` enum and the `providerToAttrs` mapping in `nix/module.nix`.

  See `docs/development/providers.md`.
- **Icon source:**
  - Add a `DashboardIconSourceType`, then subclass `JsDelivrIconSource` (or implement
    `IDashboardIconSource`).
  - Register the source and its named `HttpClient` in
    `src/Dsm.Managers/HostBuilder/HostBuilderExtensions.cs`.
  - Add its client name to `ConfigureOfflineIconHttpClients` in
    `src/Dsm.Managers.Tests/IconHttpClientStubs.cs`. Otherwise the offline manager tests can
    probe the real CDN.
  - Decide each manager's native prefix for it. Optionally add it to
    `FallbackIconSourceProviders` in `service-defaults.yaml`.

  See `docs/development/icons.md`.

## Tests

NUnit 4 on Microsoft.Testing.Platform; the test projects are executables. The full conventions
are in `docs/development/testing.md`. The ones most likely to trip you up:

- Each fixture class carries `[CancelAfter(TestTimeouts.HungThresholdMs)]` itself. In the
  pinned NUnit 4.5.1 the attribute is `Inherited = false`, so putting it on a base class won't
  apply it to the fixtures that derive from it. It's also cooperative (it only cancels a token),
  and DSM's I/O methods take no token, so it doesn't interrupt a hung test. `[TestFixture]` is
  omitted.
- Tests that reach cdn.jsdelivr.net are `[Category("Network")]`; today they are all in
  `IconResolverTests`. Other manager test hosts call `services.ConfigureOfflineIconHttpClients()`,
  so icon probes get a canned 200 instead of hitting the CDN. `ManagerTestFixtureHostedTestBase`
  does this for you, per-test hosts call it explicitly, and `IconResolverTests` deliberately
  opts out.
- `Dsm.Providers.Tests` mocks outer edges (`IDockerClient`, the Traefik client) with Moq.
  `Dsm.Managers.Tests` has no Moq reference and uses hand-rolled stubs.
- `Dsm.Shared.Tests` is shared test infrastructure (`TestHost`, the hosted-test base classes,
  `TestTempDir`, `TestDataUtilities`), not a test project.

## Releases and Nix

- Pushing a tag `X.Y.Z` or `vX.Y.Z` runs `ci.yaml`:
  1. Tests.
  2. Multi-arch images `ghcr.io/andyattebery/dashboard-services-manager:{api,provider}-<version>`,
     plus `-latest` for non-prerelease tags only. In parallel, self-contained single-file
     binaries for 6 RIDs × 2 apps.
  3. A GitHub release, which then dispatches `update-flake.yml`.
- `update-flake.yml` rewrites `version` and the per-platform hashes in `nix/package.nix`
  through `passthru.updateScript`. It builds the result on all three platforms, then pushes
  `update flake to X` to main. Don't hand-edit those values. `default.nix` exists only for
  that updater.
- The flake repackages the released provider binary; it doesn't build from source. Its
  `installCheckPhase` runs the binary and greps for `ApiUrl field is required`, the
  DataAnnotations message from `ProviderOptions.ApiUrl`. Renaming that property or changing
  its validation breaks the next release's Nix build.
- The comments in `flake.nix`, `nix/package.nix` and both workflows record measured failure
  modes: autoPatchelfHook corrupting the single-file bundle, `nix flake check` not evaluating
  modules, and a `GITHUB_TOKEN` push not triggering CI. Read them before changing those files.

## Conventions

- Async methods are named with plain verbs (`ListServices`, `WriteServices`, `GetIconUrl`). The
  only `*Async` names are ones a framework dictates (`ExecuteAsync`, `ProvideAsync`,
  `SendAsync`), plus `DashboardWriteCoordinator.WaitAsync`, which mirrors `SemaphoreSlim`.
- Call `_logger.LogDebug(...)` directly, without `IsEnabled(LogLevel.Debug)` guards.
- The docs are written for two audiences:
  - README.md and `docs/*.md` are for deployers: no `src/` links or type names. The exceptions
    are links to `src/service-defaults.yaml` and README's development material (its
    `## Development` section and its list of development docs).
  - `docs/development/*.md` are for contributors: type names, `src/` links and mechanism
    detail are expected.
